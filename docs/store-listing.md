## Detailed description

```
Formless fills forms from a profile that lives on your device, and drafts the long
answers — cover letters, "why this company", short bios — using the AI model built
into your browser.

No account. No server. No API key. Nothing you type ever leaves your browser.

WHAT IT DOES

• Fills standard fields — name, email, phone, address, work and education history —
  by reading how each form describes itself, not by guessing from position.
• Works on real, modern sites: React and Vue controlled inputs, dropdowns,
  checkboxes, radios, dates, shadow DOM.
• Drafts long-form answers with Chrome's built-in AI. It reads the job title,
  company and description on the page, then writes from your CV. Pick the tone and
  length, edit the draft, insert it when you're happy.
• Builds your profile in minutes: import a CV as PDF, or a LinkedIn data export.
• Learns from you. Fill a form by hand, click "Save filled fields to profile", and
  Formless maps what you typed back into your profile for next time.
• Several profiles — Personal, Work, per-role — switchable from the toolbar popup.

PRIVACY, CONCRETELY

Formless makes zero network requests. Not anonymised analytics — zero. There is no
backend to send anything to.

• Your profile sits in your browser's local storage.
• Optional encryption at rest: AES-GCM, with the key derived from your master
  password (PBKDF2, 210,000 iterations). The unlocked key is discarded when the
  browser closes.
• AI generation runs on-device via Chrome's built-in Gemini Nano. Your prompt never
  travels.
• Passwords, card numbers, CVV, OTP, PIN and SSN fields are never captured into your
  profile.
• Every import and capture shows you a field-by-field diff you approve.

WHAT IT WON'T DO

Formless fills and drafts. You review and submit. It never submits forms for you,
and it never tries to solve or bypass CAPTCHAs or bot detection.

OPEN SOURCE

MIT licensed and fully auditable — because "trust us with your personal data" isn't
good enough. Source, issues and roadmap:
https://github.com/itchernetski/formless

REQUIREMENTS

Any Chromium browser for form filling. AI drafting additionally needs a Chrome build
with Built-in AI available; everything else works without it.
```

## Permission justifications

Chrome asks for a one-line reason per permission. These are the answers:

| Permission | Justification |
|---|---|
| `storage` | Stores the user's profile and settings locally on their device. No remote storage is used. |
| `activeTab` | Identifies the page the user clicked the extension icon on, so the correct form is filled. |
| Host access `http://*/*`, `https://*/*` | The content script must run on the page containing the form in order to detect fields and fill them. Users can restrict this to specific sites with the built-in whitelist. |
| Remote code | None. All code is bundled in the package; nothing is fetched or evaluated at runtime. |

**Single purpose statement:**

> Formless fills web forms from a locally stored user profile and helps the user draft long-form answers to form questions using the browser's on-device AI model.

**Data usage disclosures (Chrome Web Store):** declare *none collected* for every category — personally identifiable information, health, financial, authentication, personal communications, location, web history, user activity, website content. Then check all three certifications: no selling to third parties, no use unrelated to the single purpose, no use to determine creditworthiness.

Firefox AMO wants the same in prose; the [PRIVACY.md](../PRIVACY.md) text can be pasted directly.

## Before you can submit

- [ ] Chrome Web Store developer account — one-time $5 registration fee
- [ ] Microsoft Partner Center account (free) for Edge Add-ons
- [ ] Firefox AMO account (free), and a Gecko verification pass — the Firefox manifest generated by `scripts/package.mjs` has never been loaded in Firefox
- [ ] A **publicly hosted** privacy policy URL. Chrome will not accept a file in a repo; point it at the landing page (`landing/index.html` → `/privacy`) or GitHub Pages rendering `PRIVACY.md`
- [ ] Replace `itchernetski/formless` placeholders repo-wide (see the checklist in `docs/oss-release.md`)
- [ ] Decide the store support email — `support@tchernetski.com` is used in the docs
- [ ] Publish the GitHub repo, so the source link in the listing resolves

## Submitting

**Full step-by-step mechanics — account setup, every dashboard field, privacy-tab answers, rejection playbook, update process — are in [`chrome-web-store.md`](chrome-web-store.md).** This document is the copy; that one is the procedure.

The short version:

1. `npm run package` → `release/formless-0.1.0-{chrome,firefox,edge}.zip`
2. Chrome Web Store → Developer Dashboard → New item → upload the chrome zip
3. Fill the listing from this document; upload icon and four screenshots
4. Complete the privacy practices tab exactly as above; a mismatch between declared data use and observed behaviour is the most common rejection cause
5. Publish **Unlisted** first, test a real store install, then flip to Public
6. Edge: Partner Center → new extension → upload the edge zip → same copy
7. Firefox: AMO → submit the firefox zip → paste the privacy text → expect questions about the content script's breadth

Keep the reviewed version tagged in git so a rejected listing can be diffed against what was submitted.
